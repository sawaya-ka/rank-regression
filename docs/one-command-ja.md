# 実験の実行と再接続

修復後の図を確認するだけなら、再実験は不要です。
READMEのインストール後、`rank-repro figures --group all --output-dir build/figures`で公開用データから描画できます。

## VMで再計算する場合

ローカルにPython 3.9以上と認証済みのGoogle Cloud CLI、VMにPython 3.10–3.12、`flock`、`setsid`、十分なCPU・RAM・永続ディスク空間が必要です。
科学計算パッケージのインストールにはPyPIへの接続が必要です。
VMの新規作成やIAMの変更は行いません。

```bash
bash run_gcp.sh --project YOUR_PROJECT_ID --workers 100
```

表示された一覧から対象VMを選びます。
`--project`を省略すると、現在のgcloud設定のプロジェクトを使います。
個人のプロジェクトIDやVM名は初期値に含めていません。
事前確認には`bash run_gcp.sh --dry-run`を使えます。この確認ではクラウド操作は行いません。

1. ソース・設定・元データのスナップショットを転送します。
2. SSHから独立したプロセスで実験し、ジョブごとに結果を保存します。
3. ローカルへ結果をダウンロードし、SHA-256を検証します。
4. **計算もパイプラインも成功し、ダウンロード検証も成功した場合だけ**、選択したVMの停止を要求します。

**エラー時はVMを停止しません。**
失敗・未完了のジョブは成功扱いにせず、ログと途中結果を残します。

## Macがスリープした場合

VM上の計算は継続します。
ただし、通常のdirect modeではローカルがオフラインの間はダウンロードも自動停止も完了できません。
復帰後、開始時に表示されたIDで再接続します。

```bash
bash run_gcp.sh --resume RUN_ID
```

再接続には同じプロジェクトフォルダ内の`.gcp-runs/`が必要です。
成功ジョブを再実行する指示ではありません。
既存GCSバケットを使うバックアップ・停止モードもあります。利用する場合は`bash run_gcp.sh --help`の`--gcs-prefix`を指定し、VMから読み書きできる既存バケットを使ってください。
この場合も計算成功とバックアップの読戻し検証が停止条件です。

## 失敗とソース変更を区別する

設定とソースが同じなら、クラウドでは`--resume RUN_ID --retry-failed`で失敗ジョブを再試行できます。
ローカルでは同じ出力ディレクトリで同じコマンドを再実行します。
ソースを変更したときは新しい実行になります。過去のIDを新しいソースへ付け替えたり、fingerprintを書き換えたりしないでください。
今回の修復済み18,365ジョブは別の来歴を持つ完了結果として保存しており、新しい公開コードで再び全部を計算したものではありません。

ローカルでの小さな動作確認は次のとおりです。

```bash
python tools/run_recompute_plan.py --plan configs/recompute-smoke.json --workers 2 --output-dir build/smoke
```

このsmoke planは公開結果の全面的な再計算ではありません。
