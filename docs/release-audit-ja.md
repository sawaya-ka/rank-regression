# 受領した修復結果の監査

対象は `rank-8527d9e122b5b8c5-repair-v1` の結果です。
高負荷の実験は再実行せず、受領した全チェックポイント、数値診断、集計表、来歴を照合しました。
検査した整合性と数値基準はすべて満たされています。
これは浮動小数点計算の検証であり、厳密解や制約のない最適化問題の大域最適性を証明するものではありません。

## 受領と来歴

- 元の圧縮ファイルは 546,645,073 bytes、SHA-256 は `9186dbf80fdfe6b25b67a72f05d026015a3ab022d3ed023c0c925d2db2bc48f4` です。
- 18,365 個すべてのチェックポイントの SHA-256 が来歴ファイルと一致しました。
- 成功済みの 18,346 個は親実行のチェックポイントとバイト単位で同一です。
- 修復した 19 個には別の fingerprint があり、元の失敗記録も変更せず残されています。
- 修復コード 3 ファイルの SHA-256 も記録と一致しています。
- 7 個の最終 CSV の SHA-256 が再計算 manifest と一致しました。
- チェックポイントから集計表への 744,825 フィールドの転記を照合しました。
  Student-t の自由度が 2 以下の場合の LS 無限リスクは、strict JSON では `null`、CSV では `inf` となる既知の変換を区別しています。

| ジョブの種類 | 成功数 | 確認内容 |
|---|---:|---|
| Student-t quadrature | 865 | 最後の 2 段階の相対差が 0.0005 以下、リスクが有限かつ正 |
| Lasso 理論値 | 10,000 | 選択した解のリスクが有限かつ正、残差平方が 0.00001 以下 |
| 非罰則 Rank | 2,500 | 全 25,000 反復で成功判定と primal / dual residual、duality gap の基準を確認 |
| 罰則付き推定量の修正 | 5,000 | Rank の全 250,000 反復で同じ基準を確認、変更が必要な LS / LAD も各 38,000 反復の成功を確認 |

残差、duality gap、および各許容値は、比較前に有限値であることも確認しています。
理論値の採用解における残差平方の最大値は `2.0738975022133504e-6` です。
探索途中の候補には不適格な解もあり、それらは採用解とは区別されています。

## 19 件の修復

Quadrature の 18 点は、元の 1,200 点での評価結果を残したまま積分点数を追加しました。
15 点が 2,400 点、3 点が 4,800 点で元と同じ相対差基準を満たしました。
採用時の相対差の最大値は `0.0004925858104158892` です。
この比較は数値精度の診断であり、厳密な積分誤差の上界ではありません。

非罰則 Rank の 1 点では、失敗した反復番号 4 のみを同じ seed `1830907643` で再実行しました。
ADMM の rho を `1/n = 0.001` に固定したところ、3,506 iteration で元と同じ基準を満たしました。
他の 9 反復は変更されていません。

## 公開データの範囲

受領した結果には、Figure 1–10 と Supplementary Figure S1–S2 の PDF / PNG が含まれています。
S3 の別途作成した模式図はこの実行結果には含まれず、再構成した図として区別しています。

新しい反復別データは、非罰則 Rank の 25,000 反復、罰則付き Rank の 250,000 反復、および信号生成の修正が必要だった 760 点の LS / LAD 各 38,000 反復です。
それ以外の LS / LAD は履歴から再利用した集計値であり、新しい反復別データが全推定量・全座標について揃ったわけではありません。
受領時の metadata の `replicate_level_results_available` / `replicate_level_results_included` には古い値があるため、公開用メタデータではこの範囲を明示し、受領時のメタデータも保存しました。

この圧縮ファイルの `source/` には修復用コードのみが入っています。
完全な再現用公開物には、対応する元の計算コード、設定、再利用データの来歴も併せて含めます。

## 有限な lambda 探索に関する注意

| 図 | LS | LAD | Rank | 数え方 |
|---|---:|---:|---:|---|
| Figure 7 | 0 | 7 | 0 | 集計表の `*_opt_on_boundary` フラグ |
| Figure 8 | 1 | 対象外 | 0 | 履歴表の境界フラグ |
| Figure 10・下端 | 12 | 0 | 3 | 全 5,000 点の採用 lambda を `actual_delta × 1e-4` と比較 |
| Figure 10・上端 | 76 | 0 | 0 | 全 5,000 点の採用 lambda を `actual_delta × 1000` と比較 |

Figure 7 のフラグには「有効な候補の端」が含まれ、精密化後もフラグが残る場合があります。
従って、7 点すべてが設定した lambda 区間の端にある、という意味ではありません。
うち 5 点は自由度 1、delta が約 0.05–0.05745 の範囲にあり、Rank と LAD のリスクはともにほぼ 1、差は最大でも約 `3.84e-11` です。
このような差に基づく色分けを、数値的に解決された優劣と解釈してはいけません。
残りの 2 点では最小リスクの推定量は LS です。

Figure 8 の 1 点は自由度 3、delta = 0.1 の ridge LS であり、履歴の探索上限に達しています。
Figure 8 は今回の修復で再計算しておらず、有限グリッド上の結果として公開します。

Figure 10 の新設境界フラグは、再計算していない LS / LAD 行で空欄です。
上表はその空欄を「境界ではない」と数えず、最終表の lambda と実際の `n/p` から全点について算出しています。
lambda 選択には median MSE、色分けには採用 lambda での mean MSE を用い、選択と評価で同じ反復を使っています。
これは oracle Monte Carlo comparison であり、cross-validation による実用的なチューニングの評価ではありません。
